# Mouse–human archetype conservation across IT subclasses — L4, L5 IT, L6 IT, with L2/3 as control

Implementation report for `plan/it_evo/01.l4_l5_l6_mouse_human_conservation.md`.
Scripts: `scripts/it_evo/01`–`09`. Commits `810b8e1`, `e887b72`, `8ff2f52`.

## Goal

`l23_evo` scripts `57`/`59` end a chain asking whether mouse L2/3 IT archetypes have
human counterparts: mouse archetype markers (Cheng22) are mapped through 1-to-1
orthologs, scored on human cells (Jorstad23), and rendered on both archetype
embeddings. A conserved mouse archetype concentrates at one human vertex.

This extends that evaluation to **L4, L5 IT and L6 IT**, with **L2/3 carried through the
same new code as a control**. The control does double duty: it tests pipeline
equivalence, and it tests whether the L2/3 conclusion survives a normalization
correction that `l23_evo` does not have (G2/G11 below).

## What was built

`scripts/it_evo/` — one `SUBCLASSES` config loop per script rather than four copies.
`TOKEN ∈ {L23, L4, L5IT, L6IT}`; species carried by a `human_`/`mouse_` filename prefix.

| Script | Does | Analog |
|---|---|---|
| `01.subset_jorstad23_human_it.py` | materializes human L4/L5/L6 IT h5ads from the full Jorstad23 file | — (new) |
| `02.human_jorstad23_it_varimax.py` | HVG → PCA → Kaiser varimax → variance partition | `l23_evo/01` + `05` |
| `03.refine.human_…num_archetype.py` (+ `.viz`) | NOC sweep 2–6 per human subclass | `l23_evo/08.refine` |
| `04.human_…archetype_scores_loadings.py` | seeded human PCHA, markers, scores, top cells | `l23_evo/56` |
| `05.mouse_cheng22_it_…_loadings.py` | seeded mouse PCHA on the existing `it/` varimax record | `l23_evo/58` |
| `06.mouse_it_scores_on_human_cells.py` | ortholog-mapped mouse scores on human cells | `l23_evo/60` |

untouched as a frozen record.

### Three corrections carried into the new mouse code

These are the reason the L2/3 mouse numbers are *expected* to differ from `l23_evo`:

- **G1** — the reused `it/` coords name their sample column `Sample`, not `sample`.
- **G2** — cheng22 `.X` is already `log1p(CP10k)` (max 6.40, non-integer); `.raw.X` holds
  the integer counts (max 1031). `l23_evo/18`/`58` normalize `.X` a second time.
  `it/{19,21,23,25}` correctly normalize from `.raw`, and those produced the loadings
  reused here — so scripts `05`/`09` read `.raw`.
- **G11** — the shared line `log2fc = (mean_in − mean_out) / np.log(2)` is right for the
  human `.X` (`ln(CPM+1)`) but wrong for the mouse `X_norm`, which is already
  `log2(CP10k+1)`. The division inflated every mouse log2FC by `1/ln2 = 1.443×`, so with
  `LOG2FC_THRESH = log2(1.5)` the `l23_evo` mouse filter effectively admitted genes at
  **1.32×**, not 1.5×. Dropped in `05`; made per-species in `09`.

## Gate decisions

**Gate A — human `VX_COLS`.** Keep components whose `cell_type` partial R² dominates
donor + source + library_size, then drop any whose top-|loading| genes are mitochondrial
or ribosomal (depth axes even when their `cell_type` R² looks respectable).

| Token | `vx_cols` | Dropped, and why |
|---|---|---|
| L23 | VX2,6,7,8,9,10 | published choice (VX1 libsize .70; VX3/4/5 donor) |
| L4 | VX3,4,5,6,8,10 | VX1 libsize .66; VX2 mito (MT-ND\*); VX7/VX9 donor .47/.74 |
| L5IT | VX3,5,6,8,10 | VX1 ribo/glycolysis (RPL41, LDHA/B); VX2 libsize .61; **VX4 mito despite ct .285**; VX7/VX9 donor |
| L6IT | VX6,7,8,9 | VX1 mito; VX2 libsize .63; VX3/VX4 donor .58/.70; VX5 source .31; VX10 libsize |

L6 IT has only **2** `WithinArea_cluster` levels, a near-degenerate one-dummy design that
structurally suppresses its `cell_type` R² (G4), so it was judged on *low* nuisance
loading instead. VX9 was the borderline keep (donor .100 vs cell_type .038) — see Gate B.

**Gate B — human `NOC`**, the largest NOC before `ARV_mean` jumps:

| Token | ARV_mean by NOC | Chosen |
|---|---|---|
| L23 | .005 / .020 / **.051** / .412 / .530 | **4** ✓ matches published |
| L4 | .008 / **.029** / .405 / .429 / .200 | **3** |
| L5IT | .008 / .024 / **.101** / .596 | **4** |
| L6IT | **.022** / .579 / .620 | **2** |

L6IT's floor result was checked for dependence on the borderline VX9: re-running on
`['VX6','VX7','VX8']` also breaks at 3 (ARV_mean .025 → .396), so the **2-vertex
structure is a property of the data, not of the Gate-A call**. VX9 was kept (same NOC,
marginally better per-donor agreement, 0.139 vs 0.160).

**Gate C** — mouse NOC confirmed unchanged at 3 / 3 / 2 / 3.

**Gate D** — visualization-only, confined to `07`/`08`. The L23 control carries `57`'s
human rename (A–D → D′–A′) and flip `[-1,1]`, plus mouse flip `[-1,-1]`: `05`'s triangle
correlates **+0.994** with `58`'s under `[-1,1]`, and `59` displays `58` under `[1,-1]`.
Because `05`'s vertices are permuted relative to `58`'s, `57`/`59`'s `C − A` contrast is
this record's `A − C` — same quantity, honest label. Nothing set for the other three.

## Results

### L2/3 control — the conclusion survives the correction

Translating `09`'s rows through the known mouse vertex permutation (it_evo A ≡ `26`'s C,
B ≡ B, C ≡ A):

| it_evo/09 | → human | `l23_evo/26` equivalent | → human | agree? |
|---|---|---|---|---|
| mouse_C (≡26's A) | **C** (r=0.254) | mouse_A | **C** (0.225) | ✓ |
| mouse_B (≡26's B) | **D** (0.184) | mouse_B | **D** (0.120) | ✓ |
| mouse_A (≡26's C) | **A** (0.251) | mouse_C | **B** (0.197) | near-tie |

Two of three rows agree exactly. The third is a coin flip `26` itself resolved by 0.005
(human_B 0.197 vs human_A 0.192); `09` resolves it the other way with a wider margin.
`09`'s Jaccard argmax independently agrees with its own Spearman on all three rows.

**`COMPAT_MODE` attributes the one difference.** Reverting `09`'s own two departures
(XP-space top cells, `.X` mouse normalization) gives the **identical** argmax to the main
run, r within 0.01. So neither explains the difference — it is attributable upstream to
the corrected mouse embedding (G2 changed which `VX_COLS` were selected), which `09`
cannot revert because it reads `05`'s fit. One variable isolated, as the plan intended.

**Bottom line: the G2 + G11 corrections materially change the mouse marker sets
(Jaccard ≈ 0.3–0.4 against `58`, 195 vs 227 markers) without overturning the published
L2/3 mouse→human assignment.**

### L5 IT — the cleanest new result

Both metrics agree on a 1-to-1 map, and it is partial by construction (2 mouse vs 4 human
vertices):

| Mouse | → Human | Spearman r | margin over 2nd | hypergeom p |
|---|---|---|---|---|
| A | **C** | 0.185 | 0.204 | 6.0e-17 |
| B | **D** | 0.116 | 0.088 | 1.6e-03 |

Human archetypes A and B have no mouse counterpart. The `07` figure shows a clean
two-pole `B − A` gradient with mouse B concentrating toward human D.

### L6 IT — a genuine partial negative

Human supports only 2 archetypes against mouse's 3, so a 1-to-1 map is impossible:

| Mouse | → Human | Spearman r | margin | hypergeom p |
|---|---|---|---|---|
| A | **B** | 0.170 | 0.319 | 4.5e-03 |
| C | **A** | 0.211 | 0.385 | 6.6e-11 |
| B | — | 0.027 | 0.081 | 2.6e-01 |

Two mouse archetypes map with wide margins; **mouse B has no human counterpart**
(r=0.027, p=0.26). This is the structurally expected outcome, not a defect — and the
Jaccard/Spearman disagreement on this subclass is confined to the unmatched row.

### L4 — weakest and internally inconsistent

Spearman gives a 1-to-1 permutation (A→A, B→C, C→B) but **Jaccard disagrees on mouse_B
and is not 1-to-1** (both B and C prefer human_B), and `Score B` is visually diffuse
across the whole human simplex rather than concentrating at a vertex.

| Mouse | Spearman → | r | Jaccard → | consistent? |
|---|---|---|---|---|
| A | human_A | 0.085 | human_A | ✓ but weak |
| B | human_C | 0.104 | human_B | ✗ |
| C | human_B | 0.168 | human_B | ✓ |

The only claim all three lines of evidence support is **mouse C ↔ human B**. L4 also had
the loosest per-donor agreement in the sweep: `ARV_rep` is 0.227 / 0.203 at NOC 2 / 3
against L2/3's 0.058 / 0.085, and never drops below 0.20 anywhere in the sweep. Its
donors disagree about vertex placement *at every NOC*, so this is a property of the L4
data rather than of the model-selection call — but it does mean L4's vertices, and hence
its marker sets, are the least stable of the four.

## Interpretation and caveats

**Effect sizes must be read against the control, not against zero.** The new subclasses'
|r| of 0.10–0.25 is the same magnitude as the *validated* L2/3 control (0.12–0.25 here,
0.12–0.23 in `26`). Small absolute Spearman is the scale of this assay — a rank
correlation over 313–479 ortholog log2FC values — not evidence of failure. The same holds
for Jaccard: 0.005–0.06 everywhere including L2/3, which is why `26` treated Spearman as
the headline metric and why the marker-overlap panel should not be over-read.

**What this does and does not establish.** It supports a conserved mouse→human archetype
correspondence for L5 IT (2 of 2 mouse archetypes) and L6 IT (2 of 3), and at most a
single conserved axis for L4. It does *not* establish that the unmatched archetypes have
no human counterpart in a deeper sense — only that none is detectable at the NOC the
human data support, with these markers and these orthologs.

**Known limitations.**

- **3 donors per human subclass.** `ARV_rep` is estimated from 3 groups; for L4 it is
  high at every NOC, so that subclass's vertex placement is donor-sensitive.
- **L6 IT's human `cell_type` factor is near-degenerate** (2 cluster levels), so its
  Gate-A selection rests on low nuisance loading rather than on positive cell-type
  signal. The NOC=2 result was shown robust to the borderline component, but the
  subspace itself is less well-motivated than the others'.
- **Small mouse n for L5IT (849) and L6IT (1,436).** `n_top_cells` was reduced to 100
  (from 300) so the top sets stay ≈20% of cells and remain archetype-pure and disjoint
  (G3); this necessarily makes their marker sets noisier.
- **Human and mouse ARV are not on the same scale** (G9): `03` uses 20% downsampling
  without replacement grouped by `donor_id`; `it/{20,22,24,26}` used true bootstrap
  grouped by `Sample`. Each was judged on its own elbow; absolute values are never
  compared across species.
- **NOC selection is an elbow judgment.** L5IT's `ARV_mean` at the chosen NOC=4 is 0.101,
  roughly 2× L2/3's 0.051 at its chosen NOC, though its `ARV_rep` (0.076) is as clean as
  L2/3's (0.088). Both metrics point at the same break, but NOC=3 is not absurd.
- **One archetype ordering is arbitrary.** PCHA vertex indices carry no meaning across
  fits; all cross-record comparisons here undo the permutation explicitly.

### Reproducing

```bash
conda run --no-capture-output -n archetype python -u scripts/it_evo/<script>.py
```

`03` is the long step (~1 h). `04` and `09` accept `--tokens L23 L4 …`; `09` accepts
`--compat`. Scripts `01`–`08` are deterministic given the recorded `vx_cols`/`noc`; the
only stochastic quantity anywhere is `03`'s `ARV_mean`/`ARV_std`, whose downsampling is
unseeded in both this code and `l23_evo/08.refine`.
