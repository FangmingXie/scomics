# 06. Human joint IT embedding — ordering the 13 human archetypes along the IT continuum

Script: `scripts/it_evo/22.human_it_joint_pca_archetype_map.py`
Counterpart: `scripts/it_evo/15.mouse_it_joint_pca_archetype_map.py` (plan `05.*`)

## Context

Script 15 pools all 11,061 mouse IT cells into one PCA and derives a depth order of the 11
mouse archetypes, written to `15.mouse_IT_joint_archetype_arc_order.tsv` and consumed by 12
and 14 to relabel their mouse columns `A'/B'/C'`.

There was no human counterpart. Script 04 fits the 13 human archetypes one subclass at a
time, so they share no coordinate system, and 04's markers are one-vs-each *within* a
subclass — which excludes by construction any gene roughly constant across that subclass,
i.e. exactly the laminar identity genes. The only human labeling anywhere in the repo is the
visualization-only L2/3 reversal that 07/10/12/13 carry (`archetype_1 → D'` plus a PC1
`flip`, inherited from `l23_evo/25` to match a figure's orientation), flagged *DO NOT
PROPAGATE TO ANALYSIS* and not derived from any depth statistic. Scripts 16/17 work on VX
gene-loading subspaces and never touch archetypes.

Script 22 fills that gap. Its deliverable is
`local_data/res/it_evo/22.human_IT_joint_archetype_arc_order.tsv`.

## Decisions

1. **Two-pass arc order.** Mouse 15 hardcodes a curated order; for human the order is the
   deliverable, so it cannot be. Run 1 writes the raw angular sort with `curated=False` in
   every row; the figures and diagnostics are inspected; run 2 records the curated order with
   the angular rank kept alongside. The uncurated state is loud in four places (banner printed
   twice, `curated` column, inversion count suppressed as `NOT APPLICABLE`, final status line)
   so `ARC_ORDER_CURATED = None` is a declared state rather than a silent fallback.
2. **Script 13 is wired to the result; 12 is not.** After run 2, script 13 reads the
   arc-order TSV and orders/relabels its 13 human columns by depth, mirroring how 14 consumes
   15's file for mouse (`key` columns already share the `L23_A` convention). 13's score TSVs
   keep 04's letters and column order — only the figure moves — and 13 raises if the file is
   `curated=False`. Script 12 (the cross-species grid) is untouched.
3. **No interactive HTML.** At 93,152 cells the per-category Plotly traces are not worth the
   file size. Vector PDFs only — but **three bases × two colorings**, see below.

## Differences from mouse 15

| | mouse 15 | human 22 |
|---|---|---|
| input | one pooled h5ad, 11,061 cells | **four** per-subclass h5ads, 93,152 × 29,352 |
| normalization | `.raw` → `log2(CP10k+1)` (G2) | **`.X` directly** — already `ln(CPM+1)`, as 02 does |
| gene index | `var_names` are symbols | ENSG in `var_names`; loadings keyed on `var['feature_name']` (G5) |
| variance partition | 3 factors | **4 factors** (cell_type/donor/source/**technical**) |
| archetypes | 11 | **13** (L23:4, L4:3, L5IT:4, L6IT:2) → `cmap='tab20'` |
| geometry basis | PC1-PC2 | **SPC1-SPC2** (PCA → varimax → Gate A → PCA again) |
| figures | HTML + 2 PDFs | 6 PDFs: {pc, vx, spc} × {archetype, subclass} |

Memory: the pooled dense matrix (10.9 GB) is never built. Per-gene moments accumulate in
float64 via `np.bincount` over the CSR `.indices` (scipy's `X.sum(axis=0)` accumulates in
float32 and was measured off by 0.11 absolute — unusable for ranking genes by variance); the
2000 HVG columns are then sliced sparse and densified (745 MB), asserted against
`X_hvg.astype(np.float64).var(axis=0)` at `rtol=1e-9`. Peak ~8 GB.

Pooled factors are built from plain **string** arrays, never `pd.concat` of Categoricals whose
level sets differ per file — that is how a stale-level all-zero dummy (G6) returns. Pooled
level counts asserted at 24/3/2.

**Technical block.** 02 partials `nCount_RNA` alone. Here sequencing depth, detection rate and
mitochondrial fraction (33 `MT-` genes, from `.raw`) enter as ONE 3-column `technical` factor,
because they are collinear (r = 0.835 between log10 `nCount_RNA` and `nFeature_RNA`) and
partialling them separately would split their shared variance and make every component look
cleaner than it is. Library size enters as log10 — the dependence is on the log. Per-covariate
marginal R² is printed so the block stays interpretable.

## Why the basis is SPC, not PC (the main finding)

On mouse, PC1/PC2 carry cell_type 0.86/0.90 with library_size 0.0006, so 15 reads the arc
straight off the top of the embedding. On human that fails, and fixing it took three steps:

1. **Naive PCs are mixed.** PC1 is cell_type 0.347 / technical 0.366 — it is the L4-vs-rest
   contrast *and* the complexity gradient at once (r = +0.70 with log10 `nCount_RNA`). PC2 is
   donor-dominated. This is pre-existing in the dataset, not caused by pooling: 02's
   per-subclass PC1 is library-size dominated in all four subclasses (0.570/0.555/0.089/0.141),
   which is why 04's Gate-A drops VX1 everywhere. Notably PC1's subclass R² *rises* from 0.463
   to 0.658 once library size is regressed out — the technical axis was **masking** biological
   signal, not creating it.
2. **Varimax quarantines the nuisances, one per axis** — library size + detection on **VX1**
   (technical 0.770; marginal r² 0.896 / 0.694), mitochondrial fraction on **VX2** (mito 0.506),
   donor on **VX5** (0.208). Gate A (cell_type strictly greater than donor, source and
   technical) keeps seven components, subspace purity 0.951. But varimax also *spreads* the
   cell-type signal across all seven (0.78 → 0.40): of the 21 gated planes the best reaches
   0.886 purity and **not one** keeps the four subclasses contiguous around the arc. A 2-D arc
   cannot be read there.
3. **PCA inside the gated subspace (SPC)** re-concentrates it. This is only a rotation of the
   gated subspace — it cannot recover what the gate discarded — but it puts 61% of the subspace
   variance and 0.939 of the 0.946 purity into two axes. SPC1/SPC2 come out cell_type
   0.792/0.855 with technical 0.005/0.004, i.e. the cleanest components anywhere in the
   analysis and directly comparable to mouse PC1/PC2 (0.86/0.90).

`ARC_SPC = ('SPC1', 'SPC2')` is therefore just the top two by variance — **no selection is
applied, and anatomical depth order plays no part in it**, so the subclass sequence the arc
comes out in remains independent evidence. (An earlier iteration picked a plane using depth
order as a criterion; that was circular and was removed.)

## Geometry method

Angular sort about the centroid-of-centroids, with three refinements over 15, which could
hardcode its answer and here cannot:

* the circle is cut at the **largest angular gap**, not the −180° wraparound;
* the traversal is oriented so L2/3 IT precedes L6 IT — fixing a **reading direction** only,
  since a component's sign is arbitrary;
* subclass contiguity is judged by **run-length encoding**, not `drop_duplicates` — the latter
  collapses non-consecutive repeats too, so an arc that leaves a subclass and returns counts
  as contiguous. This bug inverted an earlier conclusion and is called out in the code.

Diagnostics: per-archetype coordinates/angle/radius with an automatic `INTERIOR` flag below
`0.5 ×` median radius (the mouse `L6IT A` failure mode); the largest gap with a closed-loop
warning under `1.5 × 360/13`; **two plane scans** (gated VX and SPC) with kNN subclass purity
against the subspace ceiling; the SPC1-only order plus Spearman ρ; the class-imbalance control;
within- vs cross-subclass centroid distances and the 12 closest pairs; the
cells-per-10°-bin connectedness histogram.

The imbalance control compares top-cell centroids (300 cells each, equal by construction)
against all-cell size-weighted ones **cyclically** — the geometry is a near-closed loop, so an
order is only defined up to rotation and direction, and a linear inverted-pair count charged
36/78 against an order it in fact matches exactly.

No subsampling: class size enters only through the HVG set and the component directions, which
the imbalance control tests directly.

## Run-1 result

SPC1-SPC2 is the **only plane of the 42 scanned** (21 gated VX + 21 SPC) that keeps all four
subclasses contiguous, and it is also the highest-purity one (0.939):

```
L2/3 D → L2/3 C → L2/3 B → L2/3 A → L4 C → L4 B → L4 A
       → L5 D → L5 B → L5 C → L5 A → L6 A → L6 B
```

subclasses `L2/3 IT → L4 IT → L5 IT → L6 IT`, i.e. anatomical depth order, recovered without
being selected for. Cloud fully connected (36/36 bins, minimum 155 cells). Within-subclass
centroid median 6.17 vs cross-subclass 14.66, only 5/62 cross pairs below the within median.
The imbalance control returns THE SAME CYCLE (rotated by 6, reversed).

Open points for curation:

* **The geometry is a ring more than an open arc** — largest gap 54.3° against 27.7° for even
  spacing, only ~2×. On a near-closed loop the deep end's placement depends on where the circle
  is cut, which is why an LDA-based 1-D reading of the same subspace gives
  L2/3 → L4 → **L6 → L5** instead. The L2/3 and L4 blocks are stable; L5 vs L6 is not.
* `L2/3 B` is interior (0.49× median radius) — the least reliable of the 13 positions.
* SPC1-SPC2 reads as four fairly distinct lobes; the clean horseshoe of a 1-D gradient appears
  in **SPC1-SPC3**, not SPC1-SPC2.

## Run-2 result (curated)

`ARC_ORDER_CURATED` overrules exactly one segment: **L5 IT is taken D, C, B, A** rather than
the angular D, B, C, A. Those three centroids span 12.3° of angle (L5 B −91.9, L5 C −80.8,
L5 A −79.6) and sit 0.98–2.92 units apart — L5 A/C being the closest of all 78 pairs — so the
angular sort has no resolving power there, the same situation that forced the mouse L6IT
correction in 15. The script reports the cost as **1 inverted pair of 78** (`L5 C`/`L5 B`).

Final depth labels (04 letter → figure label):

| L2/3 IT | L4 IT | L5 IT | L6 IT |
|---|---|---|---|
| D→A', C→B', B→C', A→D' | C→A', B→B', A→C' | D→A', C→B', B→C', A→D' | A→A', B→B' |

The L2/3 column reproduces, from the joint embedding, exactly the mapping that 07/10/12/13
previously hardcoded as a viz-only reversal to match a figure's orientation — an independent
check on both. The other three subclasses were never relabelled before and now are.
