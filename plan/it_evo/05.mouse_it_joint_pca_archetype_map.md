# Plan: joint PCA of all mouse IT cells, colored by archetype assignment

## Context

The question is whether the 11 mouse IT archetypes (L2/3 A,B,C; L4 A,B,C; L5IT A,B; L6IT A,B,C)
are 11 independent programs or samples of one graded manifold spanning the four layers, so
that one archetype gradually becomes another and the two archetypes at a subclass boundary
are nearly the same point.

Nothing on disk can answer this today, for a structural reason: script `05` fits each
subclass **separately** — its own varimax subspace, its own PCHA space — so the 11 archetypes
share no coordinate system, and `05`'s markers are one-vs-each *within* a subclass, which
excludes by construction any gene roughly constant across that subclass. Laminar identity
genes are exactly such genes. Confirmed read-only: within-subclass marker Jaccard is 0.000
for all 10 pairs, and canonical depth markers are nearly absent from all 11 sets (only
`Rorb` in L23_A, `Calb1`/`Rasgrf2`/`Cux1` in L4_C, `Cdh13`/`Ccbe1` in L23_C, `Zfp804b`/`Cdh9`
in L6IT_B). A depth continuum could dominate these cells and leave no trace in `05`'s output.

A read-only probe of what *is* on disk (marker Jaccard and `14`'s cross-archetype scores,
z-scored, averaged over each archetype's top cells) found no chain — 1-D MDS explained only
44% of the affinity variance and interleaved subclasses non-laminarly — but did find three
groups recurring across layers: **I** L23_A~L6IT_A~L5IT_B, **II** L23_C~L6IT_C~L4_A~L5IT_A,
**III** L23_B~L6IT_B, with L4_B and L4_C unattached. Both signals share `05`'s marker sets
upstream, so they are less independent than they look, and both are blind to depth.

This plan builds the direct look that settles it: pool all 11,061 cells, embed them in one PC
space, and color by archetype assignment. A pooled embedding sees the between-layer genes
that per-subclass fits discard, so continuum, recurring-groups, and discrete-blocks become
visually distinguishable in one figure.

## Script `scripts/it_evo/15.mouse_it_joint_pca_archetype_map.py`

Compute plus figures in one script, as `05`/`06` already do. `15` is the next free number.

**In**
- `links/it_evo/superdupermegaRNA_cheng22_IT_P28NR.h5ad` — all 11,061 cells; the file is
  exactly the four subclasses (L4 4732, L2/3 4044, L6IT 1436, L5IT 849), verified
- `local_data/res/it_evo/05.mouse_<TOKEN>_pcha_{xp,aa}.tsv`, `05.mouse_<TOKEN>_archetype_scores.tsv`,
  `05.mouse_<TOKEN>_top_cells.tsv` (all four tokens)

**Out** (res `local_data/res/it_evo/`, fig `local_data/fig/it_evo/`)
- `15.mouse_IT_joint_pca_{coords,loadings}.tsv`, `15.mouse_IT_joint_pc_variance_partition.tsv`
- `15.mouse_IT_joint_archetype_assignment.tsv` (cell, subclass, archetype, assignment rule columns)
- `15.mouse_IT_joint_archetype_centroids.tsv` (11 x PC1..PC10)
- `15.mouse_IT_joint_pca_archetype_map.html`, `15.mouse_IT_joint_pca_archetype_map.pdf`

### Steps

1. **Embedding — `scripts/it/19.cheng22_L23_varimax.py:190-221` with one line removed.**
   Reuse that block verbatim except the `Subclass` filter at `19:193`: normalize
   `raw[:, var_names]` counts to log2(CP10k+1) (G2), top `N_HVG = 2000` by variance on the
   normalized matrix, `StandardScaler`, `PCA(n_components=10, random_state=0)`.
   Making the joint embedding the *same procedure* as the per-subclass records is the point —
   any difference between them is then the pooling, not the method.
   Do **not** substitute `scripts/common.py:select_hvg`: it normalizes by median depth and
   ranks on `log1p`, so it would silently select a different gene set than the records this
   figure is read against.
2. **Archetype assignment per cell.** Primary rule: nearest archetype vertex in that cell's
   *own* subclass PCHA space — Euclidean distance from `05.mouse_<TOKEN>_pcha_xp.tsv` rows to
   `05.mouse_<TOKEN>_pcha_aa.tsv` vertices over all PC columns — giving one of 11 labels
   (`L2/3 A` … `L6IT C`). Also emit two alternates, free to compute and useful as controls:
   argmax of `05.mouse_<TOKEN>_archetype_scores.tsv`, and a top-cells-only label from
   `05.mouse_<TOKEN>_top_cells.tsv` (2,300 extreme cells, everything else `other`).
   Fail fast if the four assignment blocks do not cover all 11,061 barcodes exactly once, or
   if any subclass's cell set differs from its `_pcha_xp.tsv` index.
3. **Archetype centroids in the joint space**: mean joint-PC coordinate of each archetype's
   top cells — 11 points, overlaid as diamonds so the vertex geometry is readable directly.
4. **Interactive figure** via `scripts/viz.py:614 scatter_categorical_html`, whose per-category
   traces and legend toggling are exactly right for "do L2/3 C and L6IT C sit together":
   `cell_metadata` = archetype (11 categories), `Subclass`, `Type`, score-argmax archetype,
   top-cells-only; `panels` = PC1/PC2, PC1/PC3, PC2/PC3; `panel_3d` = PC1/PC2/PC3;
   `arch_vis` = the 11 centroids.
5. **Static figure** via `scripts/viz.py:239 save_archetype_scatter_pdf`, once colored by
   archetype and once by subclass. Pass `cmap='tab20'` — that helper cycles
   `plt.get_cmap(cmap).colors`, so the default `tab10` would give two archetypes the same
   color at 11 categories.
6. **Variance partition of the joint PCs** by `Type` / `Sample` / `n_counts`, reusing the
   `variance_partition` function defined inline in `it/19` (it is not in `common.py`; it is
   copied across the varimax scripts, so copy it once more rather than refactoring them all).
   This says immediately whether PC1 is the depth axis or library size / sample.

## How to read the result

- **Continuum**: one connected cloud, the four subclasses ordered along a single axis, the 11
  centroids strung along it in laminar order, and adjacent subclasses' boundary archetypes
  adjacent or overlapping.
- **Recurring groups**: archetype coloring runs *orthogonal* to the subclass axis, with the
  probe's groups I / II / III each spanning several layers — the same within-layer axis
  rediscovered four times.
- **Discrete**: four separated clouds with density gaps at the boundaries.

The variance partition and the `Type` coloring arbitrate a fourth possibility — that PC1-PC2
carry sample or depth-of-sequencing structure rather than biology.

## Caveats to state in the docstring

- Pooled HVGs are dominated by between-subclass genes. That is wanted here, but it makes this
  a *new* space, not comparable to the per-subclass varimax records, and it must not be used
  to re-derive archetypes.
- Cell counts are unbalanced (4732 / 4044 / 1436 / 849), so the PCs are weighted toward L4 and
  L2/3, and L5IT contributes least.
- If the variance partition shows `Sample` dominating PC1-PC2, a Harmony-corrected variant is
  the follow-up; precedent exists in `scripts/it/28-39.harmony.*`.
- The assignment rule is a proxy: PCHA's convex weights `S` would be canonical, but `05` does
  not save them. Nearest-vertex and score-argmax are both approximations, which is why both
  are emitted.

## Verification

1. Assignment table covers all 11,061 cells exactly once; per-subclass label counts are
   non-degenerate (no archetype with ~0 cells); nearest-vertex and score-argmax rules agree on
   a reported fraction of cells — large disagreement is itself worth knowing.
2. Joint PCA sanity: explained-variance ratio for PC1-PC10 printed; PC1-PC2 not dominated by
   `Sample` or `n_counts` in the variance partition.
3. Centroid geometry cross-checked against the probe: pairwise distances among the 11
   centroids in joint PC space should place groups I / II / III together if the recurring-group
   reading is right. This is the numeric counterpart of the picture and should agree with it.
4. Render the PDF (`pdftoppm -png -r 60`) and read it against the three patterns above.

## Run

```bash
conda run --no-capture-output -n archetype python -u scripts/it_evo/15.mouse_it_joint_pca_archetype_map.py
```

Minutes: 11,061 cells x 16,572 genes is small, and the PCA is on 2,000 HVGs.

## Outcome (implemented)

The archetype centroids order around the PC1-PC2 arc as

```
L2/3 C -> L2/3 B -> L2/3 A -> L4 C -> L4 B -> L4 A -> [L6IT A] -> L5IT B -> L5IT A -> L6IT C -> L6IT B
```

Each subclass's archetypes come out contiguous without being asked to, and the subclass
sequence is cortical depth, recovered from a fit that never saw a layer label. L6IT A (the
smallest archetype, 249 cells) is the one violation. PC1/PC2 are cell-type dominated
(R² 0.86 / 0.90, `sample` ~0.00); PC3 is not usable (`sample` R² 0.45). Cell density has no
empty bin across the occupied arc, but peaks of 827 and 1353 per 10° bin at the L2/3 and L4
lobes against troughs of 33-34 at the boundaries.

**Two premises in the Context above did not survive the implementation**, and are kept here
only as the record of what was believed beforehand:

- The three recurring cross-layer groups do not appear in the depth-aware embedding — group
  II's members land at arc angles -150°, +138°, +10°, +89°. The probe rested on `05`'s
  depth-blind marker sets, exactly the failure this script was built to escape.
- Boundary archetypes do not collapse. Within-subclass centroid distance is median 7.79 vs
  18.19 cross-subclass, and only 1/45 cross pairs beats the median within-subclass pair. The
  first version of the script measured this over all 10 PCs and got a misleading ranking
  dominated by the sample-driven axes; it now asserts its geometry axes are cell-type
  dominated. The one real collapse is L4 A ~ L6IT A (d=5.30), closer than 4 of the 10
  within-subclass pairs.

Net: one connected, laminarly-ordered manifold, but with the archetypes clustered by subclass
and density troughs between them — four groups strung along a shared axis rather than one
archetype smoothly becoming the next.
