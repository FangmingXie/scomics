# Plan: cross-subclass grid — every mouse archetype score on every human IT embedding

## Context

`scripts/it_evo/10.viz.human_jorstad23_mouse_it_all_scores.py` renders all mouse archetype
scores for **one** subclass pair per PDF. That only ever shows the four *diagonal* pairs,
because script `06` only computes those: its `SUBCLASSES` loop pairs one mouse subclass with
one human h5ad, so mouse L4 markers never touch human L2/3 cells.

The question that layout cannot answer is **specificity**: does a mouse L2/3 archetype score
high in human L2/3 *and nowhere else*, or does it score high everywhere? Script `09`
quantifies the diagonal pairs but never looks off-diagonal.

Deliverable: one figure, **rows = the four human subclass embeddings (L23, L4, L5IT, L6IT),
columns = all 11 mouse archetypes** (L2/3 A,B,C; L4 A,B,C; L5IT A,B; L6IT A,B,C), with a
colorbar shared down each column so a column reads as "where in human IT does this mouse
archetype live". 4 × 11 = 44 panels.

### Why this needs new computation and a normalization change

1. **The off-diagonal scores do not exist.** `06` produces 4 score sets; the grid needs
   4 human subclasses × 11 mouse archetypes.
2. **A shared colorbar per column requires a shared scale.** `06` computes each gene's 2/98
   percentiles *within the subclass being scored* (`06:117-119`), so every subclass is
   independently rescaled to ~[0,1] and cross-row differences are normalized away. Decision
   taken: compute each gene's percentiles **once over all 93,152 pooled human IT cells**,
   then score every subclass against that one scale. Diagonal panels will therefore differ
   slightly from the committed `06` numbers — `06` and its outputs are left untouched, and
   the new script writes its own TSVs.

Pooling is safe: all four human h5ads share an identical 29,352-gene `var` in the same
order and `feature_name` is unique, so one `gene_to_idx` serves all four and the blocks
stack without reindexing (verified).

## Script `11.mouse_all_it_scores_on_all_human_cells.py`

- **In** `local_data/res/it_evo/05.mouse_<TOKEN>_archetype_markers.tsv` (all four),
  `data/human_mouse_orthologs.tsv`,
  `links/it_evo/jorstad23_human_WithinArea_<HTOKEN>.h5ad` (all four)
- **Out** `local_data/res/it_evo/11.mouse_all_archetype_scores_on_human_<TOKEN>.tsv`
  (4 files, 11 score columns each, index = cell barcode);
  `local_data/res/it_evo/11.pooled_gene_scale.tsv` (`gene, lo, hi`) for provenance

1. Ortholog map — the block from `06:60-65` verbatim, including the order of the two
   `drop_duplicates` calls.
2. Build the 11 columns: per mouse token, map each `archetype_k` marker set to human
   symbols. Key them `f'{token}_{letter}'` (`L23_A` … `L6IT_C`) and carry a display name
   (`L2/3 A`).
3. Union of the 11 human gene lists (**411 genes**); one `gene_to_idx` from
   `var['feature_name']`.
4. Per human subclass: `adata.X[:, union_cols].toarray()` — slice before densifying (G7) —
   giving `(n_cells, 411)` float32. `del adata; gc.collect()` between subclasses.
5. `np.vstack` the four blocks → `(93152, 411)` ≈ 153 MB. Compute `lo`/`hi` per gene at the
   2/98 percentile **once**, with `06`'s degenerate guard
   `rng = np.where(hi > lo, hi - lo, 1.0)`.
6. Per subclass × archetype:
   `np.clip((block[:, arch_cols] - lo_a) / rng_a, 0, 1).mean(axis=1)`.
7. Fail fast if a subclass's cell index does not match `04.human_<TOKEN>_pcha_xp.tsv`'s.

Log the mapped-ortholog count per column (expect `06`'s 88–98% retention) and the per-row
mean score, so the specificity pattern is visible before the figure exists.

## New helper `save_score_grid_pdf` in `scripts/viz.py`

`viz.py` has **no** multi-row grid helper — `save_score_scatter_pdf:167`,
`save_gene_scatter_pdf:217` and `save_archetype_scatter_pdf:263` all hardcode
`plt.subplots(1, n, ...)`, and `save_score_scatter_pdf` draws **one colorbar per panel**
(`viz.py:187`), which at 44 panels is unreadable. Add an additive function (no existing
caller changes):

```python
def save_score_grid_pdf(rows, col_names, scores, title, out_path,
                        cmap='RdBu_r', pctile=(5, 95), s=1.5, dpi=300,
                        panel_size=2.0, colorbar_title='archetype score [0–1]',
                        highlight=None):
```

- `rows`: list of dicts per human subclass — `label`, `xp`, `aa`, `aa_labels`.
- `scores[i][j]`: the length-`n_cells_i` vector for row `i`, column `j`.
- **Per-column shared limits**: `vmin/vmax` from
  `np.percentile(concat(all rows of column j), pctile)`, applied to all 4 panels in that
  column — the whole point of the figure.
- **One colorbar per column**, borrowing the spanning pattern from
  `save_gene_scatter_pdf:232` (`fig.colorbar(sc, ax=axes[:, j].tolist(), location='bottom')`).
- Row labels via `axes[i, 0].set_ylabel`; column titles across the top.
- `highlight`: set of `(i, j)` drawn with contrasting spines — marks the four diagonal
  pairs, the ones `09` quantifies.
- Points `rasterized=True`, axes/text vector. Keep `set_aspect('equal')`: all 11 panels in
  a row share one embedding so each row is internally uniform.

Roughly 22 × 9 in. Large by design — it is a survey figure.

## Verification

1. **Nothing existing is touched** — `06`, `07`, `09`, `10` outputs keep their mtimes;
   `git status` shows only the new/edited script paths.
2. **Score TSVs well-formed**: 11 columns, values in [0,1], rows 47125 / 30455 / 10537 /
   5035, each index equal to the matching `04.human_<TOKEN>_pcha_xp.tsv`.
3. **Pooled vs per-subclass sanity**: correlate the four *diagonal* columns against
   `06.mouse_<TOKEN>_archetype_scores_on_human_cells.tsv`. Expect high within-subclass
   correlation — the change reweights genes in the mean but should not reorder cells much.
   A low correlation means the pooled scale is doing something unintended.
4. **Per-column limits actually shared**: spot-check one column's `(vmin, vmax)` against
   `np.percentile(concat, (5, 95))` computed independently.
5. **Render and read it** (`pdftoppm -png -r 55`). The scientific check is the diagonal: for
   a subclass-specific archetype the bright panel in a column should be the row matching its
   own subclass. A mouse archetype scoring high across all four human subclasses is a real
   result — a generic IT program rather than a subclass identity — and directly qualifies
   how `09`'s diagonal correlations should be read.
