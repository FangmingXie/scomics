# Expand the cross-species gene universe for the L2/3 loading CCA

## Context

Script `24.viz.human_mouse_L23_gene_loadings_marginal.py` plots mouse-vs-human varimax
gene loadings projected onto the CCA axes fit by script 16. It runs on **357 genes**, of
which only **51** carry a mouse archetype label (A=20, B=8, C=23). B's n=8 makes its
marginal KDE close to meaningless.

**Why 357?** Not a marker-selection step — a *double HVG intersection*:

```
top-2000 human L2/3 HVGs (02)  ∩  1-to-1 orthologs  ∩  top-2000 mouse L2/3 HVGs (it/19) = 357
```

Measured on disk: 1718 of the human HVGs and 1859 of the mouse HVGs have a 1-to-1
ortholog, out of **12,637 orthologs expressed in both datasets**. Random overlap of two
such lists would be `1718 × 1859 / 12637 = 253`. Observed 357 — a **1.41× enrichment**.
The two HVG lists are selected independently per species (different datasets, cell
counts, normalizations) and **barely agree**; the current gene set is close to an
arbitrary sample of the ortholog universe. The repo already recorded a symptom of this
(357 vs 521 orthologs, r 0.623 vs 0.598, purely from a mouse-side HVG re-selection —
`report/it_evo/03` §Verification 4) but treated it as plumbing.

The 8–23 archetype counts have the same cause, not a marker-discovery cause: 195 mouse
markers exist, **179 of them are in the 12,637-gene universe**, and only 51 survive the
double-HVG cut.

## The fix: extend loadings out-of-sample instead of refitting

A varimax loading is just a (rescaled) correlation between a gene and the fixed cell
scores. So loadings can be computed for **any** gene without touching the PCA/varimax
basis, Gate A, or the archetypes. Derivation: `vx_scores = Z @ vx_loadings` with
`vx_loadings` having orthonormal columns, hence

```
G      = Zᵀ S / (n-1)            # Z = per-gene z-scored expression, S = saved vx_scores
M      = Sᵀ S / (n-1)            # 10×10 covariance of the varimax scores
L_ext  = G @ inv(M)
```

**Verified in this session (read-only):** `L_ext` reproduces the stored 2000-gene
loadings to **2.0e-5 (mouse, float32)** and **2.2e-6 (human)**. This is the same
universe-expansion move `l23_evo/29,30` made for regulon enrichment (2000 → 20,415);
it was never applied to the loadings side.

## Pilot results (already run, `.../scratchpad/pilot2.py`)

```
set                   n    CCA1   z1    cv1   bt1 |  CCA2   z2    cv2   bt2 | cos1 cos2
current HVG∩HVG     357   0.623  13.2  0.546  0.94|  0.488  13.5  0.414  0.90| 1.00 1.00
HVG∪HVG            3220   0.358  28.3  0.324  0.95|  0.313  32.3  0.299  0.94| 0.87 0.95
all orthologs     12637   0.305  52.7  0.277  0.97|  0.262  56.2  0.261  0.94| 0.85 0.86
markers on plot:  51/195 -> 177/195   (A/B/C: 20/8/23 -> 82/35/60)
```
(`cv` = 5-fold blocked by Ward co-expression module, R=3 seeds; `bt` = median |cos| over
200 gene bootstraps; `cos` = alignment of the fitted weight vector to the current
357-gene solution. The n=357 row reproduces the published 0.623/0.488.)

**Answer to "will more genes help?" — yes, but not by raising r.**

- **r goes down, and so does cross-validated r** (0.546 → 0.324). This is real dilution,
  not just small-n bias: the HVG∩HVG genes genuinely carry the most conserved signal per
  gene. **r is a property of the gene universe, not a quality score** — it is not
  comparable across universes and must never be quoted without n.
- **Evidence more than doubles**: z 13.2 → 28.3 (CCA1), 13.5 → 32.3 (CCA2).
- **CCA2 crosses the stability gate**: bootstrap median |cos| 0.90 → 0.94. Script 16
  currently withholds CCA2's weights and top genes because it fails `STABLE_THRESH=0.9`.
  Under the union universe CCA2 becomes reportable — the concrete scientific win, and it
  directly upgrades report 03's hedge ("real-but-not-orientation-pinned").
- **The biology does not change**: cos 0.87 / 0.95 against the current solution.
- **The B-archetype marginal becomes usable**: n=8 → n=35.

Selection by "communality rank" (top-N by loading norm in both species) was also tested
and is *worse* (bt1 0.86–0.92) besides being mildly circular. **Union-of-HVG wins** and is
the cleanest criterion to state: *any gene that drove either species' subspace*, chosen
per-species and blind to the cross-species pairing.

## Decisions taken

- Universe: report the **full ladder (357 / 3220 / 12637) as a sensitivity result**, with
  **HVG∪HVG (~3220) as the primary**.
- Scope: **L2/3 now**; build the machinery subclass-generic and treat L4/L5IT/L6IT as a
  separate follow-up decision (their axes were rejected on bootstrap instability of
  0.70–0.80, so expansion could overturn a headline in report 03 — that deserves its own
  review).
- Markers: **reuse the existing 195** from script 05. The bottleneck was the intersection,
  not marker discovery.

## Implementation

### 1. New — `scripts/it_evo/26.extend_varimax_loadings.py`

Subclass-generic (config list keyed by token, same shape as `05...py:68-72`), run for
`L23` only in this phase.

- Paths at top, capitalized, per CLAUDE.md. Inputs: the two h5ads
  (`links/it_evo/jorstad23_human_WithinArea_L23IT.h5ad`,
  `links/it/superdupermegaRNA_cheng22_IT_P28NR.h5ad`) and the saved coords
  (`02.human_<T>_varimax_coords.tsv`, `it/19.cheng22_<T>_varimax_coords.tsv`).
- **Reuse the exact normalization of the source scripts, do not re-derive it.** Human `.X`
  is already log-normalized and is used as-is (`02...py:229`). Mouse must be
  `log2(raw/depth*1e4 + 1)` from `.raw` (`it/19...py:200-205`) — the double-normalization
  bug (G2) lives here.
- Compute `L_ext` by the formula above, sparse-safe on the human side
  (`Xᵀ S` on CSC, then center with `mu ⊗ S.sum(0)`; do not densify 47125 × 29352).
- **Fail-fast gates** (no silent fallbacks): assert the recomputed loadings for the
  original 2000 HVGs match the stored TSV to `< 1e-4`; raise if any gene has zero
  variance rather than emitting NaN rows (this crashed the first pilot).
- Outputs: `26.human_<T>_varimax_loadings_full.tsv`,
  `26.mouse_<T>_varimax_loadings_full.tsv` (genes × VX1..VX10, all expressed genes), plus
  `26.<T>_gene_universe.tsv` with `human_symbol, mouse_symbol, human_detection,
  mouse_detection, in_human_hvg, in_mouse_hvg, tier` so downstream scripts never re-derive
  membership.

### 2. Modify — `scripts/it_evo/16.crossspecies_axis_matching.py`

Add a `GENE_UNIVERSE` config (`'hvg_intersect' | 'hvg_union' | 'all_expressed'`) that

`coexpression_modules`, `module_folds`, `cross_validate`, the bootstrap gate

Two things that do need attention at 9× the gene count:
- `coexpression_modules` calls `scipy.linkage` — O(n²) memory. At n=3220 that is ~40 MB
  (fine); at n=12637 it is ~640 MB. `analyze_pair` already computes it once and passes
  `modules` into `cross_validate`, so no restructuring is needed — just don't add a
  per-seed recompute.
- Write `16.<T>_universe_ladder.tsv` — one row per universe × component with
  `n, r, z, r_cv_blocked, boot_cos_median, stable, cos_to_hvg_intersect`. This table *is*
  the sensitivity result and belongs in the report.

### 4. Report — `report/it_evo/05.gene_universe_expansion.md`

Must state plainly: the 357-gene set was a 1.34×-enriched, near-arbitrary intersection;

## Results (implemented 2026-08-13)

Full write-up in `report/it_evo/05.gene_universe_expansion.md`. Delivered as planned, with
one deviation: the new script is numbered **26**, not 25, because uncommitted work
(`25.viz.wang25_multiome_it_mouse_archetype_expr_over_stage.py`) already held that slot;
this plan moved from `08.` to `09.` for the same reason.

### Measured universe

`26.L23_gene_universe.tsv`: **12,637** 1-to-1 orthologs detected in both datasets. 1718 of
the 2000 human HVGs and 1859 of the 2000 mouse HVGs are among them, so chance overlap is
**253** against the observed **357** — a **1.41× enrichment** (the Context section's 1.34×
used the whole ortholog table as the denominator; 1.41× is the correct figure). Of the 195
mouse markers, **179** are in the universe and only 51 survived the double-HVG cut.

### The ladder (`16.L23_universe_ladder.tsv`)

The universe list changed after the first implementation: `all_expressed` (12,637) was
removed and the two one-sided selections added, so the final rungs are

```
universe        n     CCA1  z1    cv1   boot1 | CCA2  z2    cv2   boot2 stable2 | cos1  cos2
hvg_intersect   357   0.623 13.0  0.525 0.94  | 0.488 13.0  0.426 0.90  False   | 1.00  1.00
human_hvg      1718   0.424 21.6  0.357 0.95  | 0.332 21.8  0.293 0.90  False   | 0.98  0.97
mouse_hvg      1859   0.408 23.2  0.344 0.93  | 0.366 27.2  0.369 0.92  True    | 0.87  0.94
hvg_union      3220   0.358 27.7  0.312 0.95  | 0.313 31.1  0.307 0.93  True    | 0.87  0.95
```

(the deleted rung was 12637 / 0.305 z51.8 cv0.284 boot0.97 | 0.262 z55.7 cv0.255 boot0.94.)

Confirms the pilot. **More genes lower r, monotonically in n, and lower the cross-validated
r too** (0.525 → 0.312), so it is genuine dilution rather than small-n optimism — the
HVG∩HVG genes carry the most conserved signal per gene. `r` is therefore a property of the
gene universe, not a quality score, and is never quoted without n.

**The two one-sided universes are not interchangeable.** `mouse_hvg` stabilizes CCA2 (2
stable pairs; boot 0.915/0.914) while `human_hvg` sits exactly on the threshold (0.905 /
0.900) and yields 1 — and CCA2 is stronger on `mouse_hvg` by every measure despite mouse
being the 11×-smaller dataset. `human_hvg` instead stays closest to the historical solution
(cos 0.98/0.97). Critically, **`human_hvg` does not fix the archetype-marker sparsity**: it
still gives A=20/B=8/C=23, identical to `hvg_intersect`, because mouse markers are mouse
HVGs by construction so requiring a human-HVG ortholog collapses back to the intersection.
Only `mouse_hvg` and `hvg_union` reach 82/35/60.

What the expansion actually buys:

1. The 1.41×-enriched accident of two HVG lists no longer determines the result.
2. Evidence roughly doubles: z 13.0 → 27.7 (CCA1), 13.0 → 31.1 (CCA2).
3. **CCA2 crosses `STABLE_THRESH`** (bootstrap median 0.90 → 0.93/0.93), so
   `16.L23_axis_cca_top_genes_union.tsv` carries **2 stable pairs** where the 357-gene file
   carried 1. CCA2's weights and gene list were previously withheld. The released list —
   SORCS3, KCNH7, GPC6, SGCZ, CDH20, PLCB4, RASGRF2, BDNF, KCNH5 — is the same
   channel/adhesion/axon-guidance program report 03 could only describe informally. This
   upgrades report 03's "real-but-not-orientation-pinned" hedge for the second dimension.
4. Archetype coverage 51 → 177 markers (A 82, B 35, C 60); B's marginal KDE was built on 8
   points, now on 35.

Biology unchanged: weights align at cos 0.87 (CCA1) / 0.95 (CCA2); CCA1 stays
human-VX2-dominated (0.908 vs 0.959) on mouse VX1 (0.89) with RORB/GRM1/SLIT3/EPHA6 leading.

### Verification outcomes

1. Reconstruction assertion **passed**: 2.2e-6 (human), 2.0e-5 (mouse, float32).
2. Refactor **inert** — all 7 `16.L23_*` files at the default universe are `diff`-identical
   to the pre-change baseline.
3. Ladder reproduces the pilot within noise.
4. Negative control at n=3220: destroyed pairing gives |blocked-CV r| ≤ 0.038 and Σcos²θ
   excess ≤ 0.006 over 5 permutations, against 0.312 / 0.307 for the true pairing.
5. Figures verified visually; all three marginals smooth, gray cloud faded not buried.
6. Extra regressions not in the original plan: `--compat` still gives n=521 and the exact
   expected spectrum, and L6IT at the default universe still gives CCA1 0.381 / z 5.70 /
   cv 0.106 / frac 0.067, matching report 03.

### Follow-up left open

L4 / L5IT / L6IT are untested under expansion and remain governed by report 03. They were
rejected as "no identifiable axis" largely on bootstrap instability of 0.70–0.80, and
expansion lifted L2/3's CCA2 from 0.90 to 0.93 — so this could overturn a headline.
`26 --tokens L4 L5IT L6IT` then `16 --ladder --tokens L4 L5IT L6IT` is the whole run.

## Not doing (and why)

- **Raising `N_HVG` from 2000.** It would re-fit both PCAs, invalidating Gate A, the NOC
  sweeps, the archetypes, the markers, and every score record — for the same information
  the projection gives for free.
- **Jointly selecting HVGs across species.** Guarantees overlap but bakes the cross-species
  comparison into the gene selection, and still cascades through both PCAs.
- **Re-running script 05's marker Wilcoxon genome-wide.** Report 01 depends on that record.
