# Re-run the mouse→human ABC score transfer on the seeded record (script 60), then re-render 57

## Context

Scripts 56/58 rebuilt the human and mouse PCHA records with a fixed seed
(`PCHA_SEED = 0`), so both are now reproducible. One link in the cross-species chain still
points at the old unseeded record: `22.human_cheng22_abc_scores.py` maps mouse archetype
markers onto human cells via orthologs, and it reads
`21.mouse_archetype_markers.tsv` (the unseeded mouse fit) plus the `09.pcha_*` human
embedding. Its output, `22.human_archetype_scores.tsv`, is exactly what figure 57 plots.

So `57.human_mouse_b_ca_scores.pdf` currently shows unseeded-mouse-derived scores on the
seeded `56.*` human embedding — a mixed-provenance figure. This task closes that gap:
re-run script 22's computation off `58.mouse_archetype_markers.tsv` as a new numbered copy
(script 60), keeping script 22 and every `22.*` output as the original record, then
re-render 57 on the result.

Two scope decisions from the user: the new script drops the TF- and CAM-restricted score
sets (only the all-ortholog scores are needed downstream), and the outputs are renamed from
the terse `human_archetype_scores` to `mouse_archetype_scores_on_human_cells`, which says what
the file actually holds — mouse-derived archetype scores evaluated on human cells, as opposed
to the human-derived `56.human_archetype_scores.tsv`.

**What actually changes numerically.** Verified before planning:

- `09.pcha_xp.tsv`, `25.human_pcha_xp.tsv`, `56.human_pcha_xp.tsv` are **byte-identical**
  (md5 `4512e883114a380f6ce334a417ca19c9`). The human cell embedding is deterministic PCA on
  the varimax coords, so seeding never affected it.
- `09` / `25` / `56` archetype vertices agree to ~0.003 in PC1/PC2.
- Therefore the only input change with real effect is `21.mouse_archetype_markers.tsv` →
  `58.mouse_archetype_markers.tsv` (225 → 227 markers, per-archetype Jaccard ≥ 0.98). The
  embedding swap to `56.*` is a provenance fix, not a numerical one, and the resulting
  scores should track `22.*` very closely.

**Outcome:** a `60.*` score record derived end-to-end from seeded fits, and
`57.human_mouse_b_ca_scores.pdf` regenerated from it.

## Approach

### Step 0 — copy this plan to `plan/l23_evo/60.reseeded_abc_score_transfer.md`

Per CLAUDE.md (plan mode blocks writing there now).

### Step 1 — `scripts/l23_evo/60.mouse_abc_scores_on_human_cells.py`

A copy of `22.human_cheng22_abc_scores.py` with paths updated and the TF/CAM branches
removed. No seeding is needed — the script has no stochastic step; it is a deterministic
ortholog map plus percentile normalization.

**Inputs** (from `22...py:42-48`):

```
IN_MOUSE_MARKERS  21.mouse_archetype_markers.tsv  ->  58.mouse_archetype_markers.tsv
IN_PCHA_XP        09.pcha_xp.tsv                  ->  56.human_pcha_xp.tsv
IN_PCHA_AA        09.pcha_aa.tsv                  ->  56.human_pcha_aa.tsv
IN_ORTHOLOGS      data/human_mouse_orthologs.tsv                          (unchanged)
INPUT_HUMAN       links/l23_evo/jorstad23_human_WithinArea_L23IT.h5ad     (unchanged)
IN_TF_LIST        links/common/transcription_factors.tsv                  (DROPPED)
IN_CAM_LIST       links/common/cell_adhesion_molecules.csv                (DROPPED)
```

**Outputs** — two, renamed:

```
OUT_SCORES      local_data/res/l23_evo/60.mouse_archetype_scores_on_human_cells.tsv
OUT_SCORE_HTML  local_data/fig/l23_evo/60.mouse_archetype_scores_on_human_cells.html
```

Columns stay `score_A, score_B, score_C`, index stays human cell barcodes.

**Code removed relative to 22** (this is most of the diff):

- `import requests` and `TF_URL` (`22...py:29`, `:61`)
- the Lambert-2018 download block (`22...py:66-73`)
- `tf_set` / `cam_set` loading (`22...py:75-82`)
- `tf_human_genes` and the `cam_human_genes` loop (`22...py:114-124`)
- the two extra `_compute_scores` calls, the two extra `_save_scores` calls, and the two
  extra `_scatter` calls (`22...py:143-144`, `:153-154`, `:174-175`)

**Code kept byte-identical:** the ortholog dedup (`22...py:88-91`), the h5ad load and
`feature_name` fallback (`22...py:93-104`), the per-archetype human gene-list build
(`22...py:106-112`), `_compute_scores` (`22...py:127-140`), `_save_scores`, and the
`_scatter` helper with its `gene_expr_scatter_html` call (`scripts/viz.py`). With only one
score set left, `_save_scores` and `_scatter` are each called once — keep them as plain
inline calls rather than helpers if that reads cleaner, but do not change the math.

Docstring gets updated Reads/Outputs blocks plus lines stating it is a copy of script 22 on
the seeded `58.*` mouse markers and the `56.*` human embedding, that `22.*` (including its
TF/CAM sets) is kept as the original record, and that the `xp` swap is cosmetic because
`09`/`56` xp are byte-identical.

  scripts/l23_evo/60.mouse_abc_scores_on_human_cells.py

~2–5 min, ~5 GB peak RSS (dominated by `adata.X.toarray()` on the 3.96 GB human h5ad).

Then a throwaway scratchpad check (not committed):

  all-gene set.

  overlap; report the numbers rather than asserting agreement.
- Confirm the `60.*` cell index equals the `56.human_pcha_xp.tsv` index (this is what 57's
  fail-fast check enforces).
