# Plot mouse A/B/C archetype scores on the human PCHA embedding

## Context

Mouse Cheng22 L2/3 IT has 3 archetypes (A, B, C; script `21`), human Jorstad23 L2/3 IT
has 4 (script `25`). We want to see **where mouse archetype identity lands in the human
cell-state space** — i.e. color human cells by a mouse-derived score, on the human
embedding used in the current human figure.

Both halves already exist and are cell-aligned:

- `22.human_cheng22_abc_scores.py` maps mouse A/B/C markers (79/57/89 genes) to human
  orthologs via `data/human_mouse_orthologs.tsv` and computes the same
  percentile-min-max per-cell score → `22.human_archetype_scores.tsv`
  (47,125 cells × `score_A/B/C`).
- `25.human_jorstad23_archetype_scores.py` produces the human PCHA embedding
  → `25.human_pcha_xp.tsv` / `25.human_pcha_aa.tsv`.

Verified: both TSVs have 47,125 rows with identical barcodes in identical order.

The gap is purely visualization. Script 22 plots its scores as HTML on the **older**
script-09 embedding; the current publication figure (`25.viz.*`, PDF) uses the script-25
embedding with a display-only PC1 flip and an A/B/C/D → D'/C'/B'/A' relabel. Nothing
renders mouse scores on that embedding.

**Outcome:** a new plots-only script producing a vector PDF — human cells on human
PC1 vs PC2, three panels colored by mouse score A, B, C, with the human archetype
polygon annotated A'–D' so mouse identity can be read against named human archetypes.

## Approach

New script `scripts/l23_evo/52.viz.human_jorstad23_mouse_abc_scores.py`, modeled directly
on `scripts/l23_evo/25.viz.human_jorstad23_archetype_scores.py` (same structure, same
display conventions, no recomputation).

### 1. Extend `save_score_scatter_pdf` with optional vertex labels

`scripts/viz.py:133` — add an optional `aa_labels=None` parameter (backward compatible;
existing callers `21.viz.*` and `25.viz.*` unaffected). When provided, annotate each
archetype diamond with `ax.annotate(label, (aa[i,0], aa[i,1]), ...)` using a small
offset, `fontsize=8`, `zorder=4`. Everything else in that function is reused as-is:
rasterized points + vector axes, per-panel percentile color clipping, equal aspect,
closing polygon, `pdf.fonttype=42`.

### 2. New script `52.viz.human_jorstad23_mouse_abc_scores.py`

Paths (capitalized, defined at top, per CLAUDE.md):

```
IN_SCORES  = local_data/res/l23_evo/22.human_archetype_scores.tsv
IN_PCHA_XP = local_data/res/l23_evo/25.human_pcha_xp.tsv
IN_PCHA_AA = local_data/res/l23_evo/25.human_pcha_aa.tsv
OUT_PDF    = local_data/fig/l23_evo/52.human_mouse_abc_scores.pdf
```

Parameters: `MOUSE_ARCHETYPE_NAMES = ['A', 'B', 'C']`, `SCORE_PCTILE = (5, 95)`,
`cmap='RdBu_r'` — matching `25.viz`.

Steps:

1. Load the three TSVs with `pd.read_csv(..., sep='\t', index_col=0)`.
2. **Fail-fast alignment check** (no silent reindexing — CLAUDE.md forbids silent
   fallbacks). Replace `25.viz`'s defensive `.reindex()` with an explicit assertion:
   ```python
   if not scores_df.index.equals(xp_df.index):
       raise ValueError(
           f'Cell index mismatch: {IN_SCORES} ({len(scores_df)}) vs '
           f'{IN_PCHA_XP} ({len(xp_df)}) — scores and embedding must be the same cells '
           f'in the same order.'
       )
   ```
   Then `scores = scores_df[['score_A', 'score_B', 'score_C']].values`.
3. **Display-only PC1 flip**, copied verbatim from `25.viz` (lines 65–75) including the
   loud comment banner, applied to both cell and archetype coords so they stay consistent:
   ```python
   FLIP = np.array([-1.0, 1.0])
   xp = xp_df[['PC1', 'PC2']].values * FLIP
   aa = aa_df[['PC1', 'PC2']].values * FLIP
   ```
4. **Human archetype vertex labels.** `25.human_pcha_aa.tsv` rows are `archetype_1..4`
   = original A, B, C, D. Under `25.viz`'s display rename (`A→D'`, `B→C'`, `C→B'`,
   `D→A'`), the labels in file-row order are:
   ```python
   AA_LABELS = ["D'", "C'", "B'", "A'"]   # file row order (archetype_1..4)
   ```
   Derive this from the same `RENAME` dict `25.viz` uses rather than hardcoding the list,
   so the two scripts cannot drift apart. Keep the same all-caps warning banner marking
   it visualization-only.
5. Call `save_score_scatter_pdf(xp, scores, ['A', 'B', 'C'], aa, aa_labels=AA_LABELS,
   title='Jorstad23 human L2/3 IT — mouse Cheng22 ABC archetype scores', ...)`.
   Panel titles come out as `Score A/B/C`; the docstring and suptitle make clear these
   are mouse-derived scores on human cells.

Docstring lists Reads/Outputs, per repo convention.

### Explicitly out of scope

- No recomputation of scores (reusing cached `22.*`), no h5ad load.
- TF- and CAM-restricted variants (`22.human_archetype_scores_TF/CAM.tsv`) not plotted —
  trivial to add later by parameterizing `IN_SCORES` / `OUT_PDF`.
- No changes to scripts 21, 22, or 25.
