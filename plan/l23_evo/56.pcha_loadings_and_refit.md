# Save PCHA inner-PCA loadings for the human L2/3 embedding (scripts 56, 57)

## Context

`25.human_pcha_xp.tsv` stores PC1–PC5 coordinates but no loadings: the PCA that maps the
6 varimax axes (`VX2, VX6–VX10`) into that 5-D PCHA space lives only in memory
(`sca.pca_.components_` / `sca.pca_.mean_`, used at
`scripts/l23_evo/25.human_jorstad23_archetype_scores.py:81` and discarded). Without it,
the PCs cannot be interpreted in gene terms or reused to project new data.

The fix is to save those parameters at the source. Two constraints from the user:

1. **Keep the current record.** Script 25 and every `25.*` output stay untouched; the
   change goes into a new numbered copy. Likewise script 54 is preserved and copied.
2. **Re-run, don't derive.** The new script re-fits and writes a fresh, self-consistent
   `56.*` record.

**Key fact driving the design:** `py_pcha.PCHA` seeds itself from the global unseeded
NumPy RNG (random furthest-sum start index at `PCHA.py:153`, random `S` init at `:168`;
`src/scomics/utils.py:86` passes no seed). The PCA half is deterministic — input is
47,125×6, so sklearn takes the `covariance_eigh` path with deterministic `svd_flip` — but
the archetype vertices are not. So the re-fit will **not** reproduce the cached `25.*`
vertices, and because the top-300-cells-per-archetype sets shift at the boundary, the
`56.*` markers and scores will differ numerically from `25.*` (qualitatively the same).
Script 56 therefore fixes the seed so the new record is reproducible from here on.

Because `56.*` is a different embedding from `25.*`, the script-54 figure has to be
regenerated against it — that is script 57.

**Outcome:** a `56.*` record carrying inner-PCA components, mean, and composed gene-level
loadings alongside the usual coords/markers/scores; and `57.*`, the 54-style two-panel
figure rendered on that new embedding.

## Approach

### Step 1 — `scripts/l23_evo/56.human_jorstad23_archetype_scores_loadings.py`

A verbatim copy of `25.human_jorstad23_archetype_scores.py` with three changes.

**a. All output paths re-prefixed `25.` → `56.`** (`OUT_RES_DIR` / `OUT_FIG_DIR`
unchanged), plus three new outputs:

```
OUT_MARKERS       56.human_archetype_markers.tsv
OUT_PCHA_XP       56.human_pcha_xp.tsv
OUT_PCHA_AA       56.human_pcha_aa.tsv
OUT_INNER_COMPS   56.human_pcha_inner_components.tsv   (new)
OUT_INNER_MEAN    56.human_pcha_inner_mean.tsv         (new)
OUT_GENE_LOADINGS 56.human_pcha_gene_loadings.tsv      (new)
OUT_SCORES        56.human_archetype_scores.tsv
OUT_ARCH_HTML     56.human_archetype_scatter.html
OUT_SCORE_HTML    56.human_archetype_scores.html
```

One new input: `IN_VARIMAX_LOADINGS = local_data/res/l23_evo/05.varimax_loadings.tsv`
(2000 genes × `VX1..VX10`). Inputs `05.varimax_coords.tsv`, `01.pca_loadings.tsv`, and the
human h5ad are unchanged.

**b. Seed the PCHA fit** — new parameter `PCHA_SEED = 0`, and immediately before
`sca.proj_and_pcha(NDIM, NOC)`:

```python
np.random.seed(PCHA_SEED)   # py_pcha uses the global RNG and takes no seed argument
```

with a comment noting this is what makes the `56.*` record reproducible, and that it is
why `56.*` will not match `25.*`.

**c. Save the loadings**, right after the existing `xp`/`aa` writes, following the
established convention in `scripts/astro/35.archetype_markers_p56_gao25.py:79-86`
(PCs as rows, VX axes as columns — matches the `sca.aa.T @ components_ + mean_` math with
no transpose):

```python
inner_comps = sca.pca_.components_[:NDIM]        # (5, 6) PCs x VX axes
inner_mean  = sca.pca_.mean_                     # (6,)
pd.DataFrame(inner_comps, columns=VX_COLS,
             index=[f'PC{i+1}' for i in range(NDIM)]).to_csv(OUT_INNER_COMPS, sep='\t')
pd.DataFrame(inner_mean.reshape(1, -1), columns=VX_COLS).to_csv(OUT_INNER_MEAN, sep='\t')

# gene-level loadings: compose genes->VX (script 05) with VX->PC (inner PCA)
vx_load  = pd.read_csv(IN_VARIMAX_LOADINGS, sep='\t', index_col=0)   # genes x VX1..VX10
gene_ld  = vx_load[VX_COLS].values @ inner_comps.T                    # (2000, 5)
pd.DataFrame(gene_ld, index=vx_load.index,
             columns=[f'PC{i+1}' for i in range(NDIM)]).to_csv(OUT_GENE_LOADINGS, sep='\t')
```

Note in a comment that the gene loadings inherit script 01/05's units — weights on
`StandardScaler`-z-scored HVG expression, not raw log-CP10k.

The docstring gets updated Reads/Outputs blocks and a line stating it is a seeded copy of
script 25 that additionally saves loadings, with `25.*` kept as the original record.

Everything downstream in the script (back-projection, top-300 selection, one-vs-each
Wilcoxon, score computation, both HTMLs) stays byte-identical to script 25.

### Step 2 — run script 56 and check the re-fit against the cached record

```
conda run --no-capture-output -n archetype python -u \
  scripts/l23_evo/56.human_jorstad23_archetype_scores_loadings.py
```

~2–5 min, ~5 GB peak RSS (dominated by the 3.96 GB h5ad read and the CSR column slice).

Then, before touching script 57, verify (throwaway check, not a committed script):

- **Loadings round-trip:** `(xn - mean) @ comps.T` reproduces `56.human_pcha_xp.tsv` to
  ~1e-12.
- **Vertex drift:** per-archetype Euclidean distance between `56.human_pcha_aa.tsv` and
  `25.human_pcha_aa.tsv` rows. Small drift (≲ 1 unit on a ±14 PC1 scale) means the same
  local optimum; large drift or a changed polygon shape means a different one and must be
  reported before proceeding.
- **Label mapping still valid:** `py_pcha` output is canonicalized by
  `XC[:, np.argsort(XC[0])]` (`src/scomics/utils.py:90`), so `archetype_1..4` stay ordered
  by PC1 and the `RENAME`/`FLIP` convention should carry over — but confirm it rather than
  assume, by checking that each `56.human_archetype_scores.tsv` column peaks near the
  vertex its primed label implies.

### Step 3 — `scripts/l23_evo/57.viz.human_jorstad23_mouse_b_ca_scores.py`
