# Save PCHA inner-PCA loadings for the mouse L2/3 embedding (scripts 58, 59)

## Context

This is the mouse counterpart of `plan/l23_evo/56.pcha_loadings_and_refit.md`, which did the
same thing for human (scripts 56, 57, now committed at `8cf9dbe`).

`21.mouse_pcha_xp.tsv` stores PC1–PC5 coordinates but no loadings: the PCA that maps the
6 mouse varimax axes (`VX1, VX2, VX6, VX7, VX8, VX10`) into that 5-D PCHA space lives only
in memory (`sca.pca_.components_` / `sca.pca_.mean_`, used once at
`scripts/l23_evo/21.mouse_cheng22_archetype_scores.py:85` and discarded). Without it, the
mouse PCs cannot be interpreted in gene terms or reused to project new data.

Same two constraints as the human plan:

1. **Keep the current record.** Script 21 and every `21.*` output stay untouched; the change
   goes into a new numbered copy. Likewise script 55 is preserved and copied.
2. **Re-run, don't derive.** The new script re-fits and writes a fresh, self-consistent
   `58.*` record.

**Key fact driving the design:** `py_pcha.PCHA` seeds itself from the global unseeded NumPy
RNG (random furthest-sum start index, random `S` init; `src/scomics/utils.py:86` passes no
seed). The PCA half is deterministic (4,044×6 input → sklearn `covariance_eigh` path with
deterministic `svd_flip`), but the archetype vertices are not. So the re-fit will **not**
reproduce the cached `21.*` vertices, and because the top-300-cells-per-archetype sets shift
at the boundary, the `58.*` markers and scores will differ numerically from `21.*`
(qualitatively the same). Script 58 fixes the seed so the new record is reproducible.

Because `58.*` is a different embedding *and* a different score set from `21.*`, the
script-55 figure is regenerated entirely against it — that is script 59. (Per the user's
decision, 59 reads all three inputs from `58.*`, unlike human 57 which kept `22.*` scores
because those are mouse-derived scores on human cells and independent of the human fit.)

**Outcome:** a `58.*` record carrying inner-PCA components, mean, and composed gene-level
loadings alongside the usual coords/markers/scores; and `59.*`, the 55-style two-panel figure
rendered on that new, self-consistent record.

## Approach

### Step 0 — copy this plan to `plan/l23_evo/58.mouse_pcha_loadings_and_refit.md`

### Step 1 — `scripts/l23_evo/58.mouse_cheng22_archetype_scores_loadings.py`

A verbatim copy of `21.mouse_cheng22_archetype_scores.py` with three changes — the same
three that separate 56 from 25.

**a. All output paths re-prefixed `21.` → `58.`** (`OUT_RES_DIR` / `OUT_FIG_DIR` unchanged),
plus three new outputs:

```
OUT_MARKERS       58.mouse_archetype_markers.tsv
OUT_PCHA_XP       58.mouse_pcha_xp.tsv
OUT_PCHA_AA       58.mouse_pcha_aa.tsv
OUT_INNER_COMPS   58.mouse_pcha_inner_components.tsv   (new)
OUT_INNER_MEAN    58.mouse_pcha_inner_mean.tsv         (new)
OUT_GENE_LOADINGS 58.mouse_pcha_gene_loadings.tsv      (new)
OUT_SCORES        58.mouse_archetype_scores.tsv
OUT_ARCH_HTML     58.mouse_archetype_scatter.html
OUT_SCORE_HTML    58.mouse_archetype_scores.html
```

**No new input constant is needed** — unlike the human case (which had to add
`IN_VARIMAX_LOADINGS = 05.varimax_loadings.tsv`), script 21 already reads
`IN_VX_LOADINGS = local_data/res/l23_evo/18.mouse_varimax_loadings.tsv` (2000 genes ×
`VX1..VX10`) at line 39 for its HVG list. That same file is the genes→VX matrix, so reuse it.
Inputs `18.mouse_varimax_coords.tsv` and the mouse h5ad are unchanged.

**b. Seed the PCHA fit** — new parameter `PCHA_SEED = 0` in the parameter block, and
immediately before `sca.proj_and_pcha(NDIM, NOC)` (currently line 76):

```python
# py_pcha seeds itself from the global NumPy RNG and takes no seed argument; fixing the
# global seed here is what makes the 58.* record reproducible (and why it will not
# reproduce the unseeded 21.* vertices).
np.random.seed(PCHA_SEED)
sca.proj_and_pcha(NDIM, NOC)
```

**c. Save the loadings**, inserted between the existing `xp`/`aa` writes (lines 78–82) and the
`aa_vx` back-projection (line 85), following the same convention as script 56 and
`scripts/astro/35.archetype_markers_p56_gao25.py:79-86` (PCs as rows, VX axes as columns —
matches the `sca.aa.T @ components_ + mean_` math with no transpose):

```python
inner_comps = sca.pca_.components_[:NDIM]        # (5, 6) PCs x VX axes
inner_mean  = sca.pca_.mean_                     # (6,)
pd.DataFrame(inner_comps, columns=VX_COLS,
             index=[f'PC{i+1}' for i in range(NDIM)]).to_csv(OUT_INNER_COMPS, sep='\t')
pd.DataFrame(inner_mean.reshape(1, -1), columns=VX_COLS).to_csv(OUT_INNER_MEAN, sep='\t')

# gene-level loadings: compose genes->VX (script 18) with VX->PC (inner PCA)
vx_load = pd.read_csv(IN_VX_LOADINGS, sep='\t', index_col=0)   # genes x VX1..VX10
gene_ld = vx_load[VX_COLS].values @ inner_comps.T               # (2000, 5)
pd.DataFrame(gene_ld, index=vx_load.index,
             columns=[f'PC{i+1}' for i in range(NDIM)]).to_csv(OUT_GENE_LOADINGS, sep='\t')
```

Note in a comment that these gene loadings inherit script 18's units — weights on
`StandardScaler`-z-scored log2(CP10k+1) HVG expression — which is *not* the same scale as the
`X_norm` matrix this script builds later for markers/scores (that one is un-z-scored
log2(CP10k+1)).

The `vx_load` read is a second read of `IN_VX_LOADINGS` (line 96 already reads it for
`hvg_genes`); keep them separate rather than hoisting, so the loadings block stays a
self-contained insert and the rest of the script remains byte-identical to 21.

The docstring gets updated Reads/Outputs blocks and a line stating it is a seeded copy of
script 21 that additionally saves loadings, with `21.*` kept as the original record.

Everything downstream (back-projection, top-300 selection, h5ad load + normalization,
one-vs-each Wilcoxon, score computation, both HTMLs) stays byte-identical to script 21.

### Step 2 — run script 58 and check the re-fit against the cached record

```
conda run --no-capture-output -n archetype python -u \
  scripts/l23_evo/58.mouse_cheng22_archetype_scores_loadings.py
```

Fast compared to the human run — the h5ad is 668 MB and only 4,044 L2/3 cells survive the
subclass filter — expect ~1–3 min.

Then, before touching script 59, verify (throwaway check in the scratchpad, not a committed
script):

- **Loadings round-trip:** `(xn - mean) @ comps.T` reproduces `58.mouse_pcha_xp.tsv` to
  ~1e-12, where `xn = 18.mouse_varimax_coords.tsv[VX_COLS]`.
- **Vertex drift:** per-archetype Euclidean distance between `58.mouse_pcha_aa.tsv` and
  `21.mouse_pcha_aa.tsv` rows. The `21.*` triangle spans PC1 ≈ −12.1 … +12.9 and PC2 ≈ −6.9 …
  +11.8, so small drift (≲ 1 unit) means the same local optimum; large drift or a changed
  triangle shape means a different one and must be reported before proceeding.
- **Label mapping still valid:** `py_pcha` output is canonicalized by `XC[:, np.argsort(XC[0])]`
  (`src/scomics/utils.py:90`), so `archetype_1..3` stay ordered by PC1 and the mouse
  `aa rows = A, B, C` convention (with `FLIP = [1, -1]`, no rename) should carry over — confirm
  it rather than assume, by checking that each `58.mouse_archetype_scores.tsv` column peaks
  near the vertex its label implies.
- **Marker sanity:** report the marker count per archetype against `21.mouse_archetype_markers.tsv`
  (225 rows total) — a comparable count means the re-fit landed in the same place.
