# Project P8 IT cells into the adult (P21) PC space, per subclass

## Context

Scripts 33–36 define the IT archetype structure on a **two-dataset Harmony embedding**
(cheng22 P28NR + yoo25 P21), and script 59 renders each layer's archetypes in the plane of
that embedding. We want to know where **P8** cells sit relative to that adult structure.

Routing P8 through the 33–36 basis is not cleanly possible: `harmonypy` has no `transform()`
for new cells, no Harmony state is persisted, and the z-score / depth-regression / PCA
statistics behind the adult fit were never saved either. Estimating the missing
`PC → H` leg was measured to be near-affine within yoo25 (R² 0.91–0.99), but it is still an
estimate, and re-running Harmony with P8 included risks absorbing the very P8-vs-adult
difference we are looking for into the batch term.

**Decision (user):** sidestep Harmony entirely. Refit PCA on **yoo25 P21 cells only**, per
subclass, and project P8 into that basis. Both ages come from the same yoo25 experiment, so
there is no cross-dataset batch effect for Harmony to remove in the first place — the
projection becomes exact and fully reproducible rather than estimated.

Archetype identity is carried over by the **marker-based score** route (the scripts 52/53
recipe), which needs no geometry in the new space and therefore no refit of PCHA.

Intended outcome: per subclass, one PC1/PC2 plane fit on P21, with P8 projected into it,
plus per-cell archetype scores for both ages on a common scale.

## Method

All file paths defined and capitalized at the top of the script, per CLAUDE.md. Load the
h5ad **once**, immediately subset to `Age ∈ {P21, P8}` (~17.8k cells), then loop subclasses —
avoids holding the full 4.76 GB object per iteration.

Per subclass, mirroring the `3X.harmony.two_*_embed.py` recipe minus the merge and minus
Harmony. The key discipline: **every statistic is fit on P21 and applied to P8**, so the P21
basis is fixed and P8 is a true projection.

1. **Subset** — `Subclass == sub_val`; split into reference (`Age == 'P21'`) and query
   (`Age == 'P8'`). Counts from `.raw`; depth from `obs['total_counts']` taken **before**
   gene subsetting. Drop mito genes (`g.lower().startswith('mt-')`).
2. **HVG on P21 only** — reuse `select_hvg(x_ref, depth_ref, 2000)` from `scripts/common.py`
   (median-depth normalize → `log1p` → top-2000 by variance; mask in original gene order).
3. **Normalize** — `log2(counts / depth * 1e4 + 1)` on the HVG subset, computed separately
   for ref and query. Do **not** call `scomics.utils.norm`: it fuses CP10k/log2 with a
   z-score over whatever matrix it is handed, which would let P8 move the P21 basis. Instead
   take `mu, sd = xr.mean(0), xr.std(0)` on P21 (ddof=0, matching `scipy.stats.zscore`),
   assert `sd > 0` (fail-fast), and apply `(x - mu) / sd` to **both** ages.
4. **Regress out library size** — fit `LinearRegression()` on P21's `log(depth) → xn_ref`
   (natural log, as in the embed scripts), subtract its prediction from P21, then apply the
   **same fitted model** to P8's log depth.
5. **PCA** — `PCA(10, random_state=0).fit(resid_ref)`; `transform` both ages. Save loadings
   (`pca.components_.T`), `explained_variance_ratio_`, and coords for both ages.

### Archetype scores (marker-based, no projection involved)

Independent of steps 1–5, so agreement with the persisted adult scores validates nothing
about the PCs but everything about the marker pipeline.

6. Read `<stem>_archetype_markers.tsv` per subclass; group genes by the `archetype` column.
   Derive `NOC` from the number of distinct archetypes present — **do not hard-code 3**;
   L5IT is NOC=2.
7. On the pooled P21+P8 matrix over the **full** gene set (not the HVGs), compute
   `log2(counts / depth * 1e4 + 1)`, clip each gene at its own `(2, 98)` percentile,
   min-max to `[0, 1]`, then average over each archetype's marker genes → `score_A`,
   `score_B`, … This is step 6 of the 33–36 follow scripts and the recipe already applied to
   AllAges cells by `scripts/it/53.yoo25_it_archetype_marker_competitive_set_test.py:310-318`.
   Pooling the clip statistics across both ages is deliberate: it puts P21 and P8 on one
   comparable scale.
8. Assign each cell `argmax` over the score columns (53's idiom) for figure coloring.

### Labels and colour

Primed letters are **read**, never hard-coded — `relabel_for(arc, token)` against
`15.mouse_IT_joint_archetype_arc_order.tsv`, exactly as `scripts/it/59` and `52` do. Colour
follows the **displayed** primed label (`A'→C0, B'→C1, C'→C2`), per `scripts/ARCHETYPE_MAPPING.md`.
Internal `archetype_1/2/3` → `A/B/C` maps to primed letters per subclass: L2/3, L4 and L5IT
are reversals, L6IT is identity.

### Figure

One PDF, 2 rows × 4 columns (columns = subclasses in laminar order L2/3, L4, L5IT, L6IT, as
in scripts 59/60). Top row P21, bottom row P8, **shared axes limits per column** so the two
ages are directly comparable. In each panel the other age is drawn first in light grey as a
reference cloud, then the panel's own cells coloured by argmax archetype.

Overlay per column: **archetype anchors** = the centroid, in the new PC1/PC2 plane, of the
P21 cells assigned to each archetype — drawn as black diamonds with the primed letter,
mirroring the overlay style of 33–36 and 59. Same P21-derived anchors on both rows, so P8's
displacement is readable against a fixed landmark. These are anchors, not PCHA vertices; the
33–36 `_pcha_aa.tsv` vertices live in the Harmony-derived space and must **not** be plotted here.

## Verification

Run: `conda run --no-capture-output -n archetype python -u scripts/it/61.yoo25_p8_project_to_p21_pcs.py`

Built-in fail-fast assertions (the script should stop, not warn):
1. Every subclass yields non-empty P21 and P8 sets with the cell counts in the table above.
2. `sd > 0` for all 2,000 HVGs on P21.
3. Depth column finite and `> 0` for both ages.
4. **Cross-check against the persisted adult scores** — restrict the recomputed P21 scores to
   the cells present in `<stem>_archetype_scores.tsv` (strip the `yoo25:` prefix; the barcode
   overlap was verified to be 2213/2213 for L2/3) and assert Pearson `r > 0.99` per archetype
   column. This catches any drift in the marker-score recipe. Note the correlation is not
   exactly 1: the persisted scores clip over the two-dataset cell set, these clip over P21+P8.
5. Assert every marker gene from the TSVs is present in the h5ad gene set (hard fail, no
   intersection fallback — matches the `astro/36` precedent).

Manual checks after the run:
- Print and eyeball `explained_variance_ratio_` for PC1/PC2 per subclass; confirm PC1+PC2 carry
  a substantial share, i.e. the plane is meaningful.
- Confirm in the PDF that P21 cells separate by archetype colour along PC1/PC2 — if the
  P21-only basis did not recover the archetype gradient, the premise of the figure fails and
  that is worth knowing before interpreting P8.
- Confirm the P8 cloud is plotted on the same axes and is not silently empty.

Expected, **not** bugs: P8 cells may sit partly outside the P21 cloud and show smaller
variance along PC1/PC2 — that is the developmental signal. P8 genes far from their P21
distribution produce large z-scores by design.

Caveats to state in the script docstring:
- No batch correction anywhere. P21a/P21b and P8a/P8b/P8c replicate variation is left in; the
  P8-vs-P21 shift is therefore confounded with any P8-specific technical batch effect.
- This PC basis is **new** and is not the 33–36 / 59 coordinate system. Do not compare these
  PC values against `_pcha_xp.tsv` or overlay `_pcha_aa.tsv`.
- Archetype identity enters only through the marker gene sets, which were called on the
  two-dataset Harmony fit.

## Follow-up: `61.v2` — the whole NR series

`scripts/it/61.v2.yoo25_nr_ages_project_to_p21_pcs.py` applies the same logic to all seven
normally-reared ages (`P6, P8, P10, P12, P14, P17, P21`), reference still P21. The dark-reared
ages (`P12DR, P14DR, P17DR, P21DR`) are excluded so a rearing manipulation does not confound
the age axis.

Only the query set widens; every fitted statistic stays P21-only. Verified: the emitted
loadings and explained-variance TSVs are **byte-identical** to 61's for all four subclasses, so
the reference basis provably does not move when more ages are projected into it.

Two scales are pooled across all seven ages rather than computed per age — the marker-score
clip and the blend rescale — because per-age normalization would renormalize each timepoint
back onto the adult palette and erase the drift the series exists to show.

Both scripts colour panels by script 59's continuous score blend, not by argmax. Argmax is kept
in the score TSVs but drives nothing: it is a hard call that zeroes out an archetype whose
markers merely shift down with age (L2/3 B' at P6/P8 reads 0.00 by argmax but 0.21-0.23 by
blend weight).

Archetype diamonds are **anchors** — the centroid of the top-decile P21 cells for each
archetype score (`ANCHOR_PCTILE = 90`), the score analogue of 33-36's "N cells nearest each
archetype". The same P21-derived anchors are drawn on every age row so displacement reads
against one fixed landmark.

Extra output beyond 61's set: `61.v2.yoo25_nr_archetype_weight_by_age.{tsv,pdf}` — mean blend
weight per (subclass, age, archetype), which is where the trajectory is actually legible.

### Revisions to 61.v2

- **Layout**: both figures are subclass-as-ROW. The embedding grid is 4 rows x 7 age columns; the
  trajectory panel is 4 rows x 1 column. Because each row is its own P21 basis, the PC variance
  shares live in the row label, not the x-label — an x-label would only ever report the bottom
  row's subclass.
- **No background cloud**: panels draw only their own timepoint. Axis limits are still shared
  across each row (and now also span the vertices), so panels stay comparable.
- **Two blends, deliberately**: panel colour is rescaled WITHIN each age, so every panel spends
  its full colour range on the spread that exists there. The trajectory keeps a POOLED blend —
  a per-age rescale would re-centre each timepoint on its own mean and flatten the drift the
  trajectory exists to plot. The marker-score clip stays pooled so score values remain
  comparable between ages.

## `62` — archetype locations fit on P21 alone

`scripts/it/62.yoo25_p21_archetype_fit_in_p21_pcs.py` runs PCHA on the P21 cells inside 61.v2's
P21 PC basis and writes the vertices in those same PC units, so 61.v2 can load and draw them.
This replaces the top-decile score centroids, which were landmarks rather than archetypes.

- Feature space PC1..PC5 with `SCA.proj_and_pcha(NDIM=5, NOC)`, mirroring 33-36's `N_ARCH_PCS=5`;
  vertices are back-projected with the 33-36 idiom `aa.T @ pca_.components_[:NDIM] + pca_.mean_`.
- NOC is derived from the 33-36 marker file, never hard-coded (L5IT is 2).
- **Vertex identity is matched, not assumed.** `scomics.utils.pcha` sorts vertices by inner-PC1,
  so the k-th vertex here is not the k-th archetype of 33-36 — it differs in 3 of 4 subclasses.
  Each vertex is labelled by the mean 33-36 marker score of its nearest P21 cells, and the
  matching must be a bijection or the script stops.
- Run order is `61.v2 -> 62 -> 61.v2`: the first pass emits the coords 62 fits in, 62 writes the
  vertices, the second pass draws them. A missing 62 file is a hard stop, not a skipped overlay.
- Verified: every vertex falls inside the P21 cell PC1/PC2 range in all four subclasses.
- Caveat: PCHA variance explained is ~0.60 for L2/3, L4 and L6IT but only **0.26 for L5IT**
  (NOC=2 on 424 cells), so the L5IT simplex is weakly determined. The vertices are also fit in
  5-D and drawn in 2-D, so the simplex edges are a projection and do not bound the 2-D cloud.

## Environment note

`py_pcha` fails under the user-site **numpy 2.2.6** in `~/.local` (`np.mat` was removed in numpy
2.0), which shadows the `archetype` env's pinned **numpy 1.26.4**. This affects every PCHA script
in the repo, not just 62. Run PCHA scripts with `PYTHONNOUSERSITE=1` so Python ignores `~/.local`:

```
PYTHONNOUSERSITE=1 conda run --no-capture-output -n archetype python -u scripts/it/62.*.py
```

## `63` — two-channel recolouring of the same embedding

`scripts/it/63.viz.yoo25_nr_bivariate_score_embedding.py` redraws 61.v2's grid with a simpler
colour rule. A `viz` script in the 59/60 mould: it recomputes nothing, reading the cached 61.v2
and 62 TSVs as-is.

61.v2's simplex blend normalises all NOC scores to sum to 1 and then desaturates by the winning
margin, so a grey cell is ambiguous between "high on everything" and "low on everything". This
figure replaces step 2 with two direct readouts:

```
d = score_C - score_A     diverging: which flanking archetype wins
b = score_B               unsigned: how much of the middle archetype
```

`d` ramps between the A and C archetype colours through neutral grey; `b` mixes that toward the
B colour, capped at `B_MAX = 0.70` so the diverging channel is never fully overwritten. Each row
carries its own 2-D colour key.

The diverging ends are read from the depth arc, never hard-coded, so they flip correctly:
L2/3 and L4 run `C' <-> A'` (letter reversals) while L6IT runs `A' <-> C'` (identity).

L5IT is NOC=2 with no `score_C`, so `d = score_B - score_A` and the b-channel is held flat — its
row is a pure diverging ramp, and its x axis means something different from the other three,
which its colour key states.

Like 61.v2's panels the rescale is per age, so colours are not comparable across age columns;
the cross-age quantity remains 61.v2's pooled weight trajectory.
